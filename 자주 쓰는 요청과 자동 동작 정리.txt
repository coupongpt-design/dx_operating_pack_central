이 파일은 작업하면서 자주 쓰는 요청 문구와, 그 말을 했을 때 Codex가 어떻게 동작하는지 정리한 치트시트다.

[새 대화 시작]
- 내가 말할 것:
  `새 대화 시작.`
- 기대 동작:
  - `PROJECT_STATUS.md` 먼저 확인
  - `docs_for_ai/CONTEXT_SNAPSHOT.md` 기본 로딩
  - 현재 포커스 2줄 요약
  - `Compact` / `Precision` 모드 선언
  - 작업 범위에 따라 관련 문서를 추가로 계속 확인
- 참고 파일:
  - `새 대화 시작 시 입력할 프롬프트.txt`

[세션 마감 handoff]
- 내가 말할 것:
  `세션 마감 패키징 해줘. 다음 대화 handoff까지 빠짐없이.`
- 기대 동작:
  - `PROJECT_STATUS.md`, `docs_for_ai/CONTEXT_SNAPSHOT.md` 우선 갱신
  - 필요 시 `DEV_LOG.md`, `now_spec.md`, `docs/dev/REAL_WORLD_QA.md`, `docs/dev/USER_JOURNEYS.md` 동기화
  - 이번 세션의 변경사항 / 결정사항 / 미해결 이슈 / 테스트 결과 / 커밋 및 git 상태 정리
  - 다음 대화용 최소 읽기 세트와 조건부 추가 문서 정리

[그냥 구현 진행]
- 내가 말할 것:
  `ㄱㄱ`
  `바로 진행`
  `구현해줘`
- 기대 동작:
  - 계획만 말하고 멈추지 않고 실제 수정까지 진행
  - 가능하면 테스트, 게이트, 커밋까지 마무리

[리뷰]
- 내가 말할 것:
  `리뷰해줘`
- 기대 동작:
  - 코드 리뷰 모드로 전환
  - 요약보다 `문제점/리스크/회귀 가능성`을 먼저 제시
  - 심각도 순, 파일/라인 기준으로 정리

[실사용 QA]
- 내가 말할 것:
  `이 흐름 QA해봐`
  `실사용 기준으로 검토해줘`
  `초보자가 쓰기 편한지 봐줘`
- 기대 동작:
  - 단위 테스트 관점이 아니라 실사용 흐름 기준으로 점검
  - `docs/dev/REAL_WORLD_QA.md`, `docs/dev/USER_JOURNEYS.md` 기준으로 검토
  - 포커스, 모달 복귀, 저장/로드, 해상도, 핫키, 실제 사용자 여정 기준으로 확인

[재현 버그 제보]
- 내가 말할 것:
  `A를 누르고 B를 했더니 C가 기대인데 D가 나옴`
- 같이 주면 좋은 정보:
  - 재현 순서
  - 기대 결과
  - 실제 결과
  - 어떤 창이 활성화였는지
- 기대 동작:
  - 재현 절차를 기준으로 원인 분석
  - 가능하면 자동 회귀 테스트 추가
  - 필요 시 문서 동기화 + 커밋까지 진행

[백업 후 진행]
- 내가 말할 것:
  `백업 한번 하고 진행`
- 기대 동작:
  - 위험한 리팩터링이나 runner/signal/StepData 변경 전 snapshot 커밋/태그/백업 포인트를 먼저 만듦
  - 그 뒤 수정 진행

[커밋까지]
- 내가 말할 것:
  `커밋까지`
  `끝까지 진행`
- 기대 동작:
  - 관련 테스트 실행
  - 필요 시 full pytest / health check / project audit 실행
  - diff 확인
  - 규칙에 맞는 커밋까지 마무리

[마크다운으로 정리]
- 내가 말할 것:
  `복붙용 markdown으로 줘`
  `마크다운 블록 하나로 정리해줘`
- 기대 동작:
  - 필요한 내용을 하나의 바깥쪽 markdown block 안에 넣어서 전달
  - 블록 밖에 중요한 내용이 새지 않게 정리

[문서 누락 없이 확인]
- 내가 말할 것:
  `필요한 문서 빠짐없이 보고 진행해줘`
- 기대 동작:
  - 최소 세트만 보고 끝내지 않음
  - 작업 범위가 드러나면 `CONTEXT_UI`, `CONTEXT_CORE`, `REAL_WORLD_QA`, `DOC_INDEX`, `ASSET_MAP` 등 관련 문서를 추가로 계속 확인
  - 실제 수정 경로와 검증 경로가 모두 커버될 때까지 확장

[주의]
- 내가 특별히 말하지 않아도 기본으로 기대해도 되는 것:
  - 작업 전 상태 확인
  - 관련 테스트 실행
  - 의미 있는 동작 변경 시 문서 동기화
  - 게이트 후 커밋
- 다만 버그 제보는 재현 순서가 구체적일수록 훨씬 정확하게 처리된다.
