이 파일은 "당연한 요청"이 아니라, 말해두면 동작이 달라지는데 나중에 잊기 쉬운 요청만 모아둔 메모다.

[1. 새 대화 시작]
- 내가 말할 것:
  `새 대화 시작.`
- 이때 기대 동작:
  - `PROJECT_STATUS.md`를 먼저 읽고 현재 상태를 파악
  - `docs_for_ai/CONTEXT_SNAPSHOT.md`를 기본 세션 스냅샷으로 로딩
  - 현재 포커스를 2줄로 요약
  - 이번 작업 모드가 `Compact`인지 `Precision`인지 먼저 선언
  - 최소 세트만 보고 끝내지 않고, 실제 수정 경로와 검증 경로가 다 커버될 때까지 관련 문서를 계속 확장해서 확인
- 추가 문서 로딩 규칙:
  - UI/layout/overlay 작업이면 `dx_operating_pack/docs_for_ai/CONTEXT_UI.md`
  - runner/StepData/serialization/테스트 작업이면 `dx_operating_pack/docs_for_ai/CONTEXT_CORE.md`
  - 실사용 버그/QA/사용성 검토면 `docs/dev/REAL_WORLD_QA.md`, `docs/dev/USER_JOURNEYS.md`, 필요 시 `docs/dev/BUG_LOOP_PROTOCOL.md`
  - 문서/규칙/운영 체계 확인이면 `docs/DOC_INDEX.md`, `docs/ASSET_MAP.md`
  - DX Pack governance/install/sync 작업이면 `dx_operating_pack/AGENT_ONBOARDING.md`
- 추가 요청:
  - 작업 범위가 넓어지거나 불확실하면 관련 문서를 더 열어줄 것
  - 구현 전에 현재 이해한 작업 범위를 짧게 정리할 것
  - 의미 있는 동작 변경이 있으면 `DEV_LOG.md`, `PROJECT_STATUS.md`, `now_spec.md` 동기화 여부를 챙길 것
  - 작업이 끝나면 필요한 테스트, 게이트, 커밋, git 상태까지 정리할 것

[2. 세션 마감 handoff]
- 내가 말할 것:
  `세션 마감 패키징 해줘. 다음 대화 handoff까지 빠짐없이.`
- 이때 기대 동작:
  - `PROJECT_STATUS.md`, `docs_for_ai/CONTEXT_SNAPSHOT.md` 우선 갱신
  - 필요 시 `DEV_LOG.md`, `now_spec.md`, `docs/dev/REAL_WORLD_QA.md`, `docs/dev/USER_JOURNEYS.md` 동기화
  - 이번 세션의 변경사항 / 결정사항 / 미해결 이슈 / 테스트 결과 / 커밋 및 git 상태 정리
  - 다음 대화용 최소 읽기 세트와 조건부 추가 문서 정리

[3. 문서 누락 없이 진행]
- 내가 말할 것:
  `필요한 문서 빠짐없이 보고 진행해줘`
- 이때 기대 동작:
  - 최소 세트만 보고 끝내지 않음
  - 작업 범위가 드러나면 `CONTEXT_UI`, `CONTEXT_CORE`, `REAL_WORLD_QA`, `DOC_INDEX`, `ASSET_MAP` 등 관련 문서를 추가로 계속 확인
  - 실제 수정 경로와 검증 경로가 모두 커버될 때까지 문서를 확장

[4. 실사용 기준 QA]
- 내가 말할 것:
  `실사용 기준으로 검토해줘`
  `이 흐름 QA해봐`
  `초보자가 쓰기 편한지 봐줘`
- 이때 기대 동작:
  - 단위 테스트 관점이 아니라 실사용 흐름 기준으로 점검
  - `docs/dev/REAL_WORLD_QA.md`, `docs/dev/USER_JOURNEYS.md` 기준으로 검토
  - 포커스, 모달 복귀, 저장/로드, 해상도, 핫키, 실제 사용자 여정 기준으로 확인

[5. 백업 후 진행]
- 내가 말할 것:
  `백업 한번 하고 진행`
- 이때 기대 동작:
  - 위험한 리팩터링이나 runner/signal/StepData 변경 전 snapshot 커밋/태그/백업 포인트를 먼저 만듦
  - 그 뒤 수정 진행

[6. 복붙용 markdown]
- 내가 말할 것:
  `복붙용 markdown으로 줘`
  `마크다운 블록 하나로 정리해줘`
- 이때 기대 동작:
  - 필요한 내용을 하나의 바깥쪽 markdown block 안에 넣어서 전달
  - 블록 밖에 중요한 내용이 새지 않게 정리

[7. 기존 GitHub 저장소 하위 폴더 편입]
- 내가 말할 것:
  `현재 열려 있는 이 프로젝트를 별도 repo로 만들지 말고, 기존 GitHub 저장소 안의 새 하위 폴더로 편입해줘`
- 이때 기대 동작:
  - 현재 열려 있는 프로젝트 폴더를 source 프로젝트로 사용
  - 대상 저장소는 `git@github.com:coupongpt-design/dx_operating_pack_central.git`
  - 인증 방식은 SSH, remote 이름은 `origin`, 기본 브랜치는 `master` 기준
  - 대상 저장소가 로컬에 없으면 clone
  - 대상 저장소 안에 현재 프로젝트 폴더명으로 새 하위 폴더를 만들고 그 안에 프로젝트를 편입
  - 새 repo를 만들지 않음
  - 업로드 제외 파일(.env, secrets, 캐시, 빌드 산출물, 개인 설정) 먼저 점검
  - 편입 범위만 diff 확인 후 대상 저장소에서 커밋 및 `origin/master` push
  - 마지막에 clone 위치, 편입된 하위 폴더명, 커밋 해시, push 결과만 짧게 요약

[메모]
- 이 파일은 "자주 쓰는 말" 모음이 아니라 "잊기 쉬운 트리거" 모음이다.
- 너무 당연한 요청(`리뷰해줘`, `ㄱㄱ`, `구현해줘`)은 일부러 적지 않는다.

8. 최신 dx pack 받게하는 프롬프트
DX 팩 최신화해.
중앙 DX PACK 원격에서 최신 내용을 바로 받아서 이 프로젝트에 적용해줘.

기준:
- remote url: git@github.com:coupongpt-design/dx_operating_pack_central.git
- branch: feature/ui-modernization-v1
- sync 방식: copy
- overwrite 적용
- 현재 프로젝트 루트를 target으로 사용

실행 기준:
python dx_operating_pack/tools/sync_dx_pack.py --remote-url git@github.com:coupongpt-design/dx_operating_pack_central.git --remote-branch feature/ui-modernization-v1 --project-root . --mode copy --overwrite

추가 조건:
- sync 전에 현재 로컬 변경과 보호 파일 상태를 먼저 확인
- sync 후 어떤 파일이 갱신됐는지 짧게 요약
- 문제가 생기면 중단하고 원인만 짧게 설명

9. dx pack이 안 깔린 프로젝트에 설치하는 프롬프트
이 프로젝트에 DX 팩 설치해.
중앙 원격은 git@github.com:coupongpt-design/dx_operating_pack_central.git 이고,
설치 후 최신 브랜치 feature/ui-modernization-v1 기준으로 한 번 더 sync해서
Gemini CLI / semi-auto 경로까지 바로 쓰게 세팅해줘.

순서:
1. git init 필요 여부 확인
2. setup_dx.py bootstrap
3. python setup_dx.py --remote git@github.com:coupongpt-design/dx_operating_pack_central.git --target-root . --mode copy --overwrite
4. python dx_operating_pack/tools/sync_dx_pack.py --remote-url git@github.com:coupongpt-design/dx_operating_pack_central.git --remote-branch feature/ui-modernization-v1 --project-root . --mode copy --overwrite
5. 설치/동기화 결과와 바로 쓸 명령 요약

추가 조건:
- SSH 인증 가능 상태인지 먼저 확인
- 기존 파일은 함부로 삭제하지 말 것
- 설치 후 hooksPath, task_finish, sync_dx_pack.py 사용 가능 여부까지 짧게 확인

설치 후 작업 마감 규칙:
- 작업 종료 시 가능하면 `python tools/task_finish.py --subject "<커밋 제목>" --auto-push` 사용
- 이 경로를 타면 수확물 생성과 중앙 DX inbox 업로드를 함께 시도함
- 단, 중앙 승격과 타 프로젝트 반영은 별도 sync 단계가 필요함
