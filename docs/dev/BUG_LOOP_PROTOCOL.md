# Bug Loop Protocol

## 목적

실사용 중 발견된 버그를 "한 번 고치고 끝"이 아니라 "다시 안 나오게 고정"하기 위한 표준 처리 루프다.

## 기본 원칙

1. 버그는 감으로 고치지 않는다. 먼저 재현 절차를 고정한다.
2. 수정은 최소 diff로 한다.
3. 수정이 끝나면 자동 회귀 테스트와 문서 계약을 남긴다.

## 표준 처리 순서

### 1. 재현 고정

- 환경: 어떤 창이 활성화되어 있었는지
- 입력: 무엇을 눌렀는지
- 기대 결과: 무엇이 되어야 하는지
- 실제 결과: 무엇이 달랐는지

### 2. 버그 분류

- UI 복귀/모달
- 저장/로드 유실
- 녹화/재생 불일치
- 포커스/단축키 충돌
- 이미지 탐색/해상도 문제
- 데이터 바인딩/러너 흐름 문제

### 3. 최소 수정

- 실제 실패 경로 한 곳을 먼저 고친다
- 관련 없는 리팩터링을 섞지 않는다

### 4. 회귀 테스트 추가

- 가능하면 pytest로 고정
- 어려우면 최소한 실사용 스모크 절차를 `USER_JOURNEYS` 기준으로 명시

### 5. 문서 반영

- 동작 계약이 바뀌면 `now_spec.md`
- 최근 상태/검증 결과가 의미 있게 바뀌면 `PROJECT_STATUS.md`
- 세션별 원인/수정/검증 기록은 `DEV_LOG.md`

## 필수 산출물

- 재현 절차 3~5줄
- 수정 위치
- 회귀 테스트 이름
- 검증 결과

## Multi-Agent와의 관계

- Planner: 재현 절차와 리스크 축 정의
- Executor: 최소 수정과 테스트 추가
- Guardian: 실사용 흐름 기준으로 누락 검토

중요한 점은, 이 프로토콜은 역할 분담을 보조할 뿐이며 QA 자체를 대체하지 않는다.
