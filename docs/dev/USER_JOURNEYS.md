# User Journeys

## 목적

이 문서는 실사용 기준 QA에서 고정으로 검증할 대표 사용자 여정을 정의한다.
각 여정은 "실제로 이 프로그램을 쓰는 사람"이 밟는 순서를 기준으로 한다.

## 핵심 여정

### J01. 처음 실행 후 첫 스텝 만들기

- 앱 실행
- 빈 상태에서 `녹화 시작`, `화면 보고 클릭 추가`, `키/마우스 동작 추가`, `예제로 시작` 중 하나로 진입
- 스텝이 실제 리스트에 추가되고 저장 가능한 상태여야 한다

### J02. 정확 재현형 녹화

- `Record` 버튼 또는 단축키로 녹화 시작
- 클릭, 드래그, 스크롤, 키 입력을 수행
- 녹화 종료 후 각 step이 기대 타입으로 생성되고 재생 시 같은 맥락에서 동작해야 한다

### J03. 이미지 스텝 캡처/편집/확정

- 이미지 추가
- 캡처 후 이미지 편집 팝업 진입
- 편집 중 ROI/추가 캡처를 해도 원래 팝업으로 복귀해야 하며 `OK`로 확정 가능해야 한다

### J04. 상대 타겟 탐색 설정

- 앵커 이미지 캡처
- `Capture Target`로 보조 이미지 지정
- `Pick Search Area`로 탐색 밴드 지정
- 저장 후 다시 열어도 보조 이미지와 탐색 설정이 유지되어야 한다

### J05. 매크로 창 비활성 상태 핫키 사용

- 대상 앱을 활성화한 상태에서 `Add Image`, `Add Action`, `Record` 관련 단축키 사용
- 매크로 창을 다시 클릭하지 않아도 기대 동작이 시작되어야 한다

### J06. JSON 저장/로드

- 작업 중인 매크로를 `.json`으로 저장
- 앱을 다시 열어 같은 파일 로드
- 캡처 이미지, 상대 타겟, 좌표, 조건, 딜레이가 유지되어야 한다

### J07. MACRO 패키지 저장/로드

- `.macro` 패키지로 저장
- 다른 경로에서 다시 로드
- 자산 파일을 포함한 이미지 기반 step이 깨지지 않아야 한다

### J08. 대상 창 포커스 전환 실행

- 매크로 창과 대상 창을 오가며 실행
- 클릭, 휠, 입력, 이미지 탐색이 대상 창 기준으로 안정적으로 동작해야 한다

### J09. 해상도/창 크기 변화 실행

- 창 크기 또는 UI scale이 달라진 상태에서 이미지 step 실행
- px 기반 step은 한계를 인지한 채 동작 여부를 보고, ratio 기반 상대 탐색은 가능한 범위에서 유지되어야 한다

### J10. 실패 후 복구

- 중간 실패, 이미지 미탐지, 정지 버튼, 긴급 중단, 다시 실행
- 워커/타이머/다이얼로그/핫키 상태가 꼬이지 않고 다음 실행이 가능해야 한다

## 우선순위

- 매 작업마다 최소 `J02`, `J03`, `J04`, `J06` 중 해당 경로를 다시 밟는다
- 릴리즈 전에는 `J01`~`J10`을 전체 확인한다

## 기록 방식

- PASS: 실제 사용자 동선 기준으로 끝까지 성공
- FAIL: 중간 복귀 실패, 저장 후 유실, 포커스 충돌, 위치/좌표 불일치, 예상과 다른 실행
