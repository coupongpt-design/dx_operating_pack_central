# Real-World QA Guide

## 목적

이 문서는 "테스트는 통과하지만 실제 사용에서는 깨지는 문제"를 줄이기 위한 운영 기준이다.
`docs/dev/MULTI_AGENT_PROTOCOL.md`가 작업 역할 분리를 정의한다면, 이 문서는 실제 사용자 흐름에서 무엇을 검증해야 하는지를 정의한다.

## 핵심 원칙

1. 기능 단위보다 사용자 여정을 먼저 검증한다.
2. UI, 포커스, 모달, 저장/로드, 해상도, 단축키, 런타임 타이밍을 별도 리스크로 취급한다.
3. 실사용 버그는 반드시 `재현 절차 + 자동 회귀 테스트 + 문서 계약` 3종 세트로 닫는다.
4. "코드상 맞다"보다 "사용자가 실제로 성공한다"를 PASS 기준으로 둔다.

## QA 레이어

### 1. 작업 중 스모크

- 버그 수정 직후 3~5분 안에 확인할 핵심 흐름
- 예: 다이얼로그 열기/닫기, 저장 후 재실행, 핫키, 녹화 시작/정지, 대상 창 포커스 전환

### 2. 릴리즈 전 실사용 스모크

- 핵심 사용자 여정 전체를 짧게 한 번씩 통과시키는 수동 체크
- 기준 시나리오는 `docs/dev/USER_JOURNEYS.md`

### 3. 자동 회귀 테스트

- 재현 가능한 버그는 가능한 범위에서 pytest로 고정
- 저장/로드, runner, dialog return, hotkey, recorder 같은 상태 전이 경로를 우선 자동화

## 실사용에서 자주 깨지는 축

- 포커스: 매크로 창 비활성 상태에서 단축키/캡처/실행이 기대대로 동작하는가
- 모달 복귀: ROI 선택, 파일 선택, 설정 팝업 이후 원래 다이얼로그가 복귀하는가
- 저장/로드: 세션 중 설정한 값이 `.json`/`.macro` 저장 후 그대로 남는가
- 녹화/재생: 녹화된 클릭, 드래그, 스크롤, 딜레이가 실제로 같은 맥락에서 재생되는가
- 해상도/배율: 창 크기, DPI, UI scale이 달라져도 이미지 탐색과 클릭 영역이 유지되는가
- OS 입력: pyautogui 입력, 휠, 글로벌 핫키, 대상 창 활성화 여부가 충돌하지 않는가

## 실행 기준

### 버그 수정 작업

- 수정 전: 재현 절차를 3~5줄로 적는다
- 수정 후: 같은 절차를 실제로 다시 밟는다
- 가능하면: 같은 실패를 자동 회귀 테스트로 추가한다

### 기능 추가 작업

- "어떤 사용자가 어떤 순서로 눌렀을 때 무엇이 되어야 하는가"를 먼저 적는다
- happy path만이 아니라 복귀 경로, 저장 후 재시작, 포커스 전환까지 본다

## 수집해야 할 증거

- 앱 상태: 어떤 창이 활성화되어 있었는지
- 입력 상태: 클릭/휠/핫키/드래그 중 무엇을 했는지
- 저장 상태: 메모리에서만 보이는지, 저장 후에도 남는지
- 화면 상태: 해상도, 창 크기, UI scale, 대상 앱 상태
- 산출물: 스크린샷, 로그, macro 파일, 실패한 step 내용

## PASS / FAIL 정의

- PASS: 실제 사용 절차를 다시 밟았을 때 기대 동작이 끝까지 이어진다
- FAIL: 중간에 UI가 사라지거나, 저장 후 값이 유실되거나, 대상 창/좌표/포커스가 달라져 다른 동작을 하면 FAIL
